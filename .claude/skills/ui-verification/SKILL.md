## 前提: レンダリングテストは書けない

`vite.config.ts` は `environment: 'node'` 固定で jsdom は未導入（依存を増やさない方針）。
そのため全画面で次の分担を取っている。**新しい画面でも踏襲すること。**

1. **判定・整形ロジックを純粋関数に切り出して export し、単体テストする**
   （例: `resolveAlertKeyId` / `computeProgressLabel` / `resolveKeyboardVisible` / `formatBestRecord`）
2. **見た目は `npm run dev` で実際にブラウザを開いて確認する**

`src/App.tsx` を一時的に書き換えて確認用の画面を出してよいが、**確認後は必ず
`git checkout -- src/App.tsx` で戻す**こと。

## 実際に踏んだバグのパターン

いずれも「実装者のブラウザ目視では気づかず、レビューで発見された」もの。同じ罠を踏まないこと。

### 1. 同値 props では CSS アニメーションが再生されない

同じキー・同じ文字を**連続でミス**したとき、props が同値のままだと React が再レンダリングせず、
CSS animation が再生されない。**1 回目しか光らない。**
design.md §3.3 の「同じ文字で 3 回連続ミス」は同一キー連打が前提なので、この状況は頻出する。

このリポジトリでは 2 通りの解法を採っている（どちらも検証済み）:

- **`Keyboard`**: 打鍵ごとに増える `missSeq` を受け取り、対象キーの React `key` を変えて
  **その 1 キーだけ再マウント**する。他のキーは `key` 据え置きで memo が bail out するため
  16ms 要件に影響しない。
- **`DrillText`**: DOM を直接触って reflow を強制し、`React.memo` を壊さずに再生させる。

**`missSeq` は単調非減少でなければならない。** 減ると「ミスしていないのにシェイク＋赤フラッシュ」
が誤発火する。`PracticeScreen` は `RESET` を dispatch しないことで構造的に保証しており、
**新しいセッションは `App.tsx` が `key`（`sessionKey`）を変えて再マウントする**ことで成立している。
この前提を崩さないこと。

### 2. 状態クラスが基本スタイルを上書きして消す

`KeyCap` で運指カラー（`border-bottom`）が `.keycap--next/--miss/--alert` の `border-color` に
上書きされ、**3 連続ミス時にまさに助けたいキーの指色が消えていた**。
状態クラスは `background-color` / `box-shadow` のみを使い、`border-color` を触らない方針に修正済み。

**状態クラスを足すときは、基本スタイルと同じプロパティを奪っていないかカスケードを追うこと。**

### 3. コントラスト比は必ず計算して確認する

design.md §4 の要件は**テキスト 4.5:1 以上・非テキスト 3:1 以上**。
目視では判定できない。`theme.css` の実色値で計算すること。実際に見つかった不足:

- Shift ハイライト時のラベル **1.82:1**（詳細度で `--text-dim` が状態色の継承に勝っていた）
- 3 連続ミス点滅のピーク **2.17:1**（keyframes の `100%` で文字色を変えていなかった）
- `--text-dim` / `--border` のトークン自体が基準未満 → **t18 で値を調整済み**
  （現在: `--text-dim` 5.07:1 / 4.64:1、`--border` 3.31:1 / 3.03:1）

**`--text-dim` を本文サイズで使う前に、現在値でのコントラストを再確認すること。**

### 4. 色だけに依存しない

design.md §4 の要件。運指は色＋指名テキスト（`FINGER_LABELS`）、
ヒートマップは濃淡＋数値、合否は色＋記号（`✓` / `✗`）で伝えている。

## ブラウザ確認で必ず見る項目

見た目を変えたときの最低限:

- **同じ文字・同じキーを 2 回続けてミスして、2 回とも反応するか**（上記 1）
- 3 連続ミスでヘルプ強制介入（該当キーの点滅＋運指ガイド）が出るか。
  **`showKeyboard = false` の設定でも出るか**（キーボードを強制表示する実装になっている）
- 初回起動（`localStorage.clear()` 後）でクラッシュせず、空状態が出るか
- `|` と `l`、`0` と `O` が判別できるか（design.md §10.2 の明示要件）

## その他

- アニメーションは **150ms 以内**に統一（design.md §10.3）。長い演出はテンポを壊す。
  結果画面のタイプライター演出だけは例外だが、**演出中も操作をブロックしない**こと。
- `theme.css` はトークン専用。コンポーネント固有のスタイルは同居 `.css` に置き、
  クラス名を `.keyboard__key` のようにコンポーネント名で prefix する。
- 子に**新規オブジェクト・配列・インライン関数を props で渡さない**こと。
  `Keyboard` / `DrillText` / `KeyCap` の `React.memo` が無効化され、打鍵ごとに全体が再描画される
  （design.md §4 の 16ms 要件に反する）。primitive だけを渡す。
