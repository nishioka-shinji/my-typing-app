# タイピング練習アプリ 設計書

- **プロジェクト名**: my-typing-app（仮）
- **作成日**: 2026-08-27
- **ステータス**: ドラフト（実装前レビュー待ち）

---

## 1. 背景と目的

### 1.1 背景

利用者（開発者本人・1名）は自己申告で以下すべてに該当する。

| 課題 | 内容 |
|---|---|
| キーの位置を覚えていない | ホームポジションの概念を意識していない |
| キーボードを見ないと打てない | 目線が画面と手元を往復する |
| ミスタイプが多い | バックスペース連打が常態化 |
| とにかく遅い | 特定の指・キーで停止する |

つまり **「速度改善」ではなく「ゼロからのタッチタイピング獲得」** が課題である。

### 1.2 目的

最終ゴールは **Shell / Git コマンドをキーボードを見ずに打てる状態**。
ただしそこへ直行はしない。記号だらけのコマンド（`git commit -m "..."`, `ls -la | grep foo`）は
ホームポジション未習得の状態では難易度が高すぎ、確実に挫折する。

そのため本アプリは **8 段階のカリキュラムで基礎から積み上げ、最終レベルで実務コマンドに到達する** 設計とする。

### 1.3 成功の定義

| 指標 | 目標 |
|---|---|
| Lv1〜Lv4（英字全域）クリア | タッチタイピングの土台が完成 |
| Lv8（Git コマンド）クリア | 正確率 95% 以上・150 KPM 以上で実務コマンドを打てる |
| 継続 | 1 セッション 3〜5 分で終わるため毎日続けられる |

### 2.1 スコープ外（やらないこと）

意図的に落とす。理由も明記する。

- **日本語ローマ字入力練習** — 今回のゴールがコマンド入力のため
- **サーバー同期・ランキング・SNS 共有** — 1 人用のため不要
- **モバイル / タブレット対応** — 物理キーボード前提のため意味がない
- **JIS 配列対応** — US 固定。将来対応できるようレイアウトはデータ駆動にしておく
- **音声・BGM** — 初期リリースでは入れない（Phase 4 の検討事項）

## 3. 機能要件

### 3.1 カリキュラム（レベル定義）

全 8 レベル。**前のレベルに合格するまで次はロックされる。**

| Lv | 名称 | 練習対象 | 出題内容 | 合格基準 |
|---|---|---|---|---|
| 1 | ホームポジション | `a s d f` `j k l ;` `g h` | ランダム 1〜4 文字の羅列 | 正確率 97% / 60 KPM |
| 2 | 上段 | `q w e r t` `y u i o p` | 上段＋ホーム段の混合 | 正確率 96% / 70 KPM |
| 3 | 下段 | `z x c v b` `n m , . /` | 全英字ランダム | 正確率 96% / 80 KPM |
| 4 | 英単語 | 全英字 | 短い英単語（3〜8 文字） | 正確率 96% / 100 KPM |
| 5 | 数字と基本記号 | `0-9` `- = / . , ;` | 数字列・バージョン番号・パス断片 | 正確率 95% / 100 KPM |
| 6 | Shift ＆ シェル記号 | `~ ! @ # $ % ^ & * ( ) _ + { } \| : " < > ?` | 記号単体〜2 文字の組み合わせ | 正確率 94% / 90 KPM |
| 7 | 実践 Shell | 上記すべて | `ls -la`, `cd ../src`, `grep -rn "foo" .`, `chmod +x run.sh` | 正確率 95% / 130 KPM |
| 8 | 実践 Git | 上記すべて | `git commit -m "fix: typo"`, `git rebase -i HEAD~3`, `git push origin HEAD` | 正確率 95% / 150 KPM |

**設計意図**

- Lv1〜3 で「指がキーの位置を覚える」段階を強制的に踏ませる
- Lv6 を単独レベルにしたのは、Shell/Git の難所が **英字ではなく Shift ＋ 記号** だから。
  `|` `~` `$` `"` `-` は Lv7 以降で頻出するため、事前に単体で潰す
- Lv7/Lv8 は「意味のあるコマンド」を打たせる。実務で使う筋肉と直結させ、練習が仕事に転用される感覚を作る

### 3.2 セッション仕様

- 1 セッション ＝ **20 問**（レベルごとに設定可能）
- 制限時間なし。1 問ずつ確実に打ち切る
- セッション終了時に合否判定 → 合格なら次レベル解放

**合格判定**

```
合格 = (正確率 >= レベル基準正確率) AND (KPM >= レベル基準KPM)
```

不合格でも記録は残り、弱点分析には反映される（＝無駄打ちにならない）。

### 3.3 タイピングエンジン（ミス時「進めない」方式）

苦手な人にとって最重要の仕様。**誤った指の動きを筋肉に記憶させない**ことが狙い。

**状態遷移**

```
[待機] --正しいキー--> カーソル+1 --最後の文字--> [問題クリア] --> 次の問題
   |
   +--誤ったキー--> ミス記録 + 視覚/振動フィードバック + カーソルは動かない
```

**詳細ルール**

| 状況 | 挙動 |
|---|---|
| 正しいキー | カーソルを 1 進める。文字を「確定済み」表示に |
| 誤ったキー | カーソルは動かさない。対象文字を赤フラッシュ＋シェイク。ミスカウント +1 |
| 同じ文字で 3 回連続ミス | 画面内キーボードの該当キーを強調点滅させ、運指ガイドを自動表示（ヘルプ強制介入） |
| Backspace | **無効**（押しても何も起きない）。進めない方式では消すものがないため |
| Shift / Ctrl / Alt / Meta 単独 | 無視（ミスに数えない） |
| Escape | セッション中断確認 |
| IME ON 検出 | `isComposing` を検知したら警告バナー「英数入力に切り替えてください」 |

**「ミスに数えない」キーの扱いは重要**。修飾キー単独押下をミス扱いすると、
Shift を押す動作そのものがペナルティになり Lv6 が成立しない。

### 3.4 画面内キーボード（US 配列）

- 画面下部に US 配列キーボードを常時描画
- **次に押すキーをハイライト**（最重要機能。手元を見る必要をなくす）
- Shift が必要な文字（`|` `~` `"` など）は **左右どちらかの Shift も同時にハイライト**
  - どちら側の Shift を光らせるかは「対象キーと反対の手」ルールで決定
    （例: `|`（右手 `\`）→ 左 Shift を光らせる）
- ミスしたキーは一瞬赤く光る

### 3.5 運指ガイド

各キーを担当指で色分けする。US 配列の標準運指に準拠。

|---|---|---|
| 左小指 | `` ` `` `1` `q` `a` `z` `Tab` `CapsLock` `Shift` | `#f97583` |
| 左薬指 | `2` `w` `s` `x` | `#ffab70` |
| 左中指 | `3` `e` `d` `c` | `#ffea7f` |
| 左人差指 | `4` `5` `r` `t` `f` `g` `v` `b` | `#85e89d` |
| 右人差指 | `6` `7` `y` `u` `h` `j` `n` `m` | `#79b8ff` |
| 右中指 | `8` `i` `k` `,` | `#b392f0` |
| 右薬指 | `9` `o` `l` `.` | `#d2a8ff` |
| 右小指 | `0` `-` `=` `p` `[` `]` `\` `;` `'` `/` `Enter` `Shift` | `#f692ce` |
| 親指 | `Space` | `#8b949e` |

表示モードは 3 段階（設定で切替）。

1. **常時表示** — 初心者向け（Lv1〜3 のデフォルト）
2. **ミス時のみ表示** — 中級（Lv4〜6 のデフォルト）
3. **非表示** — 卒業（Lv7〜8 のデフォルト）

レベルに応じて自動的に補助を減らしていく。**補助を外す設計まで含めて初めてタッチタイピング習得になる。**

### 3.6 弱点分析・特訓メニュー

**キーごとの弱点スコア算出**

```
missRate(k)  = ミス回数(k) / 打鍵試行回数(k)
latency(k)   = 直前の確定打鍵から正解までの平均所要ミリ秒
weakScore(k) = 0.65 * norm(missRate(k)) + 0.35 * norm(latency(k))
```

- `norm()` は全キー中での 0〜1 正規化（min-max）
- 試行回数 5 回未満のキーは信頼性が低いため対象外
- 直近 5 セッションに重み 1.0、それ以前は 0.5 の減衰をかける（過去の苦手を引きずらせない）

**特訓メニュー生成**

- 弱点スコア上位 5 キーを抽出
- そのキーを 40% 以上の頻度で含む問題を 20 問自動生成
- ホーム画面に「弱点特訓 — `p` `;` `/` `|` `~` が苦手です」として提示
- 特訓セッションはレベル解放判定には影響しない（純粋な補習枠）

### 3.7 記録・統計

localStorage に保存し、ホーム画面と結果画面に表示する。

- レベル別ベスト記録（KPM / 正確率）
- 直近 20 セッションの KPM・正確率推移（軽量な折れ線グラフ）
- 総打鍵数・総練習時間・連続練習日数（ストリーク）
- キー別ヒートマップ（弱点の可視化）

> ヒアリング時に「統計グラフ」は選択されなかったが、**弱点分析の実装に打鍵ログが必須**であり、
> グラフはその副産物として低コストで追加できるため含めた。不要なら設定で非表示にできる。

## 4. 非機能要件

| 項目 | 要件 |
|---|---|
| 入力レイテンシ | キー押下から画面反映まで **16ms 以内**（1 フレーム）。ここが遅いと練習にならない |
| 初回表示 | 1 秒以内（ローカル起動・依存を最小限に） |
| 描画 | 打鍵ごとの再レンダリング範囲を「現在の問題行 ＋ 該当キー」に限定する |
| データ耐性 | localStorage 破損・スキーマ不一致時はクラッシュせず初期化して起動 |
| 保存容量 | 打鍵ログは集計済みサマリのみ保持し、生ログは直近 5 セッション分に限定（5MB 上限対策） |
| アクセシビリティ | 色だけに依存しない（運指は色＋指名テキスト併記）。コントラスト比 4.5:1 以上 |
| ブラウザ干渉 | `Tab` `/` `'` `Space` などのブラウザ既定動作を `preventDefault` で抑止 |

## 6. データモデル

```ts
// ---------- カリキュラム定義（静的データ） ----------

type LevelId = 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8;

type GuideMode = 'always' | 'onMiss' | 'never';

interface LevelDef {
  id: LevelId;
  name: string;
  description: string;
  /** 問題生成に使う文字集合。ランダム生成レベルで使用 */
  charset?: string[];
  /** 固定問題リスト。Lv7/Lv8 のようにコマンドを出すレベルで使用 */
  items?: DrillItem[];
  /** 生成方式 */
  generator: 'randomChars' | 'words' | 'fixedList';
  questionCount: number;
  passAccuracy: number;   // 例: 0.96
  passKpm: number;        // 例: 100
  defaultGuideMode: GuideMode;
}

interface DrillItem {
  text: string;
  /** Lv7/Lv8 で表示する意味の説明 */
  hint?: string;
}

// ---------- 実行時の状態 ----------

interface TypingState {
  levelId: LevelId;
  items: DrillItem[];
  currentIndex: number;    // 何問目か
  cursor: number;          // 現在の問題内での文字位置
  startedAt: number;       // epoch ms
  lastKeyAt: number;       // 直前の確定打鍵時刻（latency 計算用）
  correctCount: number;
  missCount: number;
  /** 同一文字での連続ミス回数。3 でヘルプ強制介入 */
  consecutiveMiss: number;
  keyStats: Record<string, KeyStat>;
}

interface KeyStat {
  attempts: number;        // 正解 + ミス
  misses: number;
  totalLatencyMs: number;  // 平均算出用の総和
}

// ---------- 保存データ ----------

interface SessionRecord {
  id: string;              // uuid
  levelId: LevelId | 'weakness';  // 弱点特訓は 'weakness'
  playedAt: number;
  durationMs: number;
  accuracy: number;        // 0..1
  kpm: number;
  correctCount: number;
  missCount: number;
  passed: boolean;
  keyStats: Record<string, KeyStat>;
}

interface LevelProgress {
  unlocked: boolean;
  cleared: boolean;
  bestKpm: number;
  bestAccuracy: number;
  playCount: number;
}

interface Settings {
  guideMode: GuideMode | 'auto';
  showKeyboard: boolean;
  highlightNextKey: boolean;
  soundEnabled: boolean;
  questionCount: 10 | 20 | 30;
  levelLockEnabled: boolean;
  showStats: boolean;
}

interface AppData {
  schemaVersion: number;   // 現在 1
  progress: Record<LevelId, LevelProgress>;
  /** 直近 20 件のみ保持（それ以前は集計に畳んで破棄） */
  sessions: SessionRecord[];
  /** 全期間の累積キー統計（弱点分析の母数） */
  aggregateKeyStats: Record<string, KeyStat>;
  totals: {
    totalKeystrokes: number;
    totalTimeMs: number;
    streakDays: number;
    lastPlayedDate: string; // 'YYYY-MM-DD'
  };
  settings: Settings;
}
```

### 6.1 localStorage スキーマ

| キー | 値 |
|---|---|
| `my-typing-app:v1` | `AppData` を JSON 化した文字列（単一キーに集約） |

**読み込み時の防御**

1. `JSON.parse` を try/catch
2. `schemaVersion` を検証。不一致ならマイグレーション関数を通す
3. マイグレーション不能なら初期値で起動し、旧データは `my-typing-app:v1:backup` に退避
4. どの段階でも例外を画面に出さない（練習開始を絶対に妨げない）

## 7. アーキテクチャ

### 7.1 方針

- **状態管理ライブラリは入れない**。React の `useReducer` ＋ Context で足りる規模
- タイピングエンジンは **純粋関数のリデューサとして React から分離**する。
  これによりロジックだけを単体テストでき、UI 変更の影響を受けない
- カリキュラム定義は **データとして分離**。レベル追加＝データ追加だけで済むようにする
- キーボードレイアウトも **データ駆動**（将来の JIS 対応を安く残す）

### 7.3 タイピングエンジンの中核

```ts
type TypingAction =
  | { type: 'KEY_PRESS'; key: string; at: number }
  | { type: 'NEXT_QUESTION' }
  | { type: 'RESET' };

function typingReducer(state: TypingState, action: TypingAction): TypingState;
```

- `KEY_PRESS` は **1 文字のキーのみ**を受け取る（修飾キー単独は hook 側で捨てる）
- 期待文字 `expected = items[currentIndex].text[cursor]` と厳密比較（大文字小文字を区別）
- 一致 → `cursor++`, `correctCount++`, latency を `keyStats` に加算, `consecutiveMiss = 0`
- 不一致 → `missCount++`, `consecutiveMiss++`, `cursor` は据え置き
- `cursor === text.length` になったら問題クリア → `NEXT_QUESTION`

**この関数は DOM にも React にも依存しない**ため、そのまま Vitest でテストできる。

## 8. 主要ロジック仕様

### 8.1 指標の計算

```ts
// 正確率: 誤打鍵を含めた総打鍵に対する正打鍵の割合
accuracy = correctCount / (correctCount + missCount);

// KPM: 1 分あたりの正しい打鍵数（本アプリの主指標）
kpm = correctCount / (durationMs / 60000);

// WPM: 参考値。英語圏慣例に合わせ 5 打鍵 = 1 語
wpm = (correctCount / 5) / (durationMs / 60000);
```

**KPM を主指標にする理由**: Shell/Git コマンドは英単語ではないため WPM（語基準）は
実感と乖離する。打鍵数ベースの KPM のほうが記号練習の進捗を正しく表す。
WPM は一般的な指標なので参考表示にとどめる。

### 8.2 合否判定

```ts
passed = accuracy >= level.passAccuracy && kpm >= level.passKpm;
```

- 合格したら `progress[levelId].cleared = true` と次レベルの `unlocked = true` を立てる
- 一度解放したレベルは以後ロックし直さない

### 8.3 問題生成

| generator | 生成方法 |
|---|---|
| `randomChars` | `charset` から重み付きランダムに 1〜5 文字の塊を生成。同一文字の 3 連続は避ける |
| `words` | `words.ts` からレベルの `charset` に収まる単語のみを抽出してシャッフル |
| `fixedList` | `items` をシャッフルして先頭 `questionCount` 件 |

**弱点特訓モード**では、弱点キーを含む問題の出現重みを 3 倍にして `randomChars` を回す。

### 8.4 ストリーク（連続練習日数）

- セッション完了時に `lastPlayedDate` と今日を比較
- 同日 → 据え置き / 前日 → +1 / それ以前 → 1 にリセット
- 日付は端末ローカルタイムで判定

## 9. キー入力ハンドリングの注意点

実装時にハマるポイントを事前に潰しておく。

| 論点 | 方針 |
|---|---|
| イベント種別 | `keydown` を使う。`keypress` は非推奨、`input` は物理キーを取れない |
| 文字の取得 | `event.key` を使う（`keyCode` は非推奨）。Shift 適用後の文字が入るため記号もそのまま取れる |
| 修飾キー単独 | `event.key.length > 1` かつ `Shift/Control/Alt/Meta/CapsLock` は無視 |
| ショートカット | `ctrlKey` / `metaKey` が立っている打鍵は無視（ブラウザ操作を妨げない） |
| ブラウザ既定動作 | `Tab`（フォーカス移動）、`Space`（スクロール）、`/`・`'`（Firefox のクイック検索）を `preventDefault` |
| IME | `event.isComposing === true` なら打鍵を捨て、警告バナーを表示 |
| CapsLock | `getModifierState('CapsLock')` で検知し「CapsLock が ON です」と警告 |
| キーリピート | `event.repeat === true` は無視（押しっぱなしの連打を防ぐ） |
| フォーカス | 練習画面は `<div tabIndex={0}>` にフォーカスを当て、`window` ではなく要素で購読 |
| Dead key | US 配列では発生しないため対応不要 |

### 10.2 タイポグラフィ

- 問題文フォント: `ui-monospace, SFMono-Regular, "SF Mono", Menlo, monospace`
- 問題文サイズ: 32px（記号の判別を最優先。`|` と `l`、`0` と `O` が見分けられること）
- 等幅フォント必須（カーソル位置がずれないため）

### 10.3 フィードバック

| イベント | 演出 |
|---|---|
| 正打鍵 | 文字が緑に確定。カーソルが 1 つ右へスライド（80ms） |
| ミス | 対象文字が赤フラッシュ（120ms）＋ 問題文全体を横に 4px シェイク |
| 3 連続ミス | 画面内キーボードの該当キーが点滅、運指ガイドを自動表示 |
| 問題クリア | 行が上へフェードアウト、次の問題がフェードイン（150ms） |
| セッション合格 | 結果画面で `✓ PASSED` をタイプライター風に表示 |

**アニメーションは 150ms 以内**に統一する。長い演出は練習のテンポを壊す。

## 13. 未決事項・要判断

1. **合格基準の KPM 値は仮置き**。Phase 1 完了後、実際の記録を見て再調整する。
   初期値が高すぎると Lv1 で詰まって終わるため、迷ったら下げる。
2. **Lv4 の英単語リスト**をどこから持ってくるか（自前で 300 語程度用意する想定）。
3. **Lv7/Lv8 のコマンド集**の粒度。危険なコマンド（`rm -rf`）は練習題材から除外するか要判断
   （打つ練習をすること自体は無害だが、筋肉が覚えると事故る可能性がある。**除外を推奨**）。
4. **効果音**を入れるか。打鍵音は上達実感に効く一方、実装と素材調達のコストがある。Phase 4 で判断。
5. **公開するか**。localStorage のみなので Vercel 等に置いても問題はないが、初期スコープ外。
